# 分页后端上线后的调查记录

本记录对应captures/paged-7的合成复现实验。系统沿用production-stack入口，CPU后端
生成张量与阶段屏障；下述现象不宣称来自真实客户数据或GPU实测。

部署配置与旧健康看板都显示可服务，但结构化响应在不同采集顺序下偶尔发生改变。
分片分别解码时未见溢出，跨rank合并后某些候选却改变；同一份query换一个后端导出顺序，
预览结果仍相同，最终文本可能不同。常规logits协议请求不受同样影响。

页分配侧认为重传没有新增页，服务侧却有时过早拒绝下一个请求；另一组轨迹恰好相反，
新请求被接受后才发生工作区不足。只看终态计数，两组都可能归零。取消发生在query之前、
query之后或第二个commit之前时，已有文本、页缓存与租户占用的差异需要分别观察。

发布期间，同一资源名称与模型别名保持不变。新请求恢复正常不代表此前在途请求也正确；
导出中的部分页仍携带旧的词表、投影与语法上下文。KV表的position、slot和窗口position
来自不同计数器；按文件行号检查时，故障未能稳定复现。

旧attention_pilot.py用于容量notebook的预览，保留在工程中作为历史调用路径。
请结合原始导出、实际生产入口、公开契约和连续checkpoint确定修复范围。
不要求采用某个固定内核、内部类名、存储表或排查顺序。
