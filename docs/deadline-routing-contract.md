# Deadline routing contract 1.0

This document defines the author extension, not historical upstream guarantees.
The gateway supports one process, multiple heterogeneous endpoints, text
`POST /v1/completions` with `stream: true`, and an absolute integer
`deadline_us`. A monotonic microsecond clock governs all event times. Request
IDs are unique within a gateway session; absent X-Request-Id is generated by the
existing gateway. HTTP metadata must remain compatible with the upstream path.

## Calibration and placement

Every endpoint declares model, model revision, tokenizer version, transport_us
and a nonnegative two-dimensional calibration surface. `tokens` and `decodes`
start at zero, strictly increase, and contain at least two nodes. service_us
rows correspond to decode nodes and columns to token nodes. Between nodes use
bilinear interpolation; beyond either final node extend the last segment.
Negative extrapolated service time is clamped to zero. Decimal input values
are the calibration values, not truncated integer buckets.

Local tokenization is authoritative. codepoint-v1 yields Unicode code points;
utf8-v1 yields UTF-8 bytes. Caller prompt_tokens is informational and must not
replace tokenizer output. A custom async tokenizer can be supplied at boot.

A cache claim has endpoint_id, model_revision, tokenizer, prefix (token IDs),
matched_tokens, created_at_us, expires_at_us. Only a matching namespace, a
matching prefix and inclusive validity interval may contribute. Clip match to
[0, token count], take the largest valid match, and use zero on unavailable
lookup. A cache miss does not make the endpoint unavailable. Cache lookup is an
asynchronous boundary; local queries can overlap other request admission.

For each healthy, non-draining matching endpoint, compute:

    predicted absolute first-token time = now
      + external backlog
      + current local prefill reservations
      + correction * surface(uncached tokens, external decodes + local decodes)
      + transport_us

Preserve intermediate precision. Round the final nonnegative timestamp to the
nearest integer microsecond, half-up. Select the smallest timestamp not later
than deadline_us; ties choose the lexicographically smallest endpoint_id.
No feasible endpoint is 429, no usable load observation/healthy endpoint is
503, and no configured model is 404. A query-string endpoint hint must not bypass
the deadline policy. Deadline mode does not reroute connection failures.

## Load observations

A snapshot carries endpoint_id, observed_at_us, sample_seq and by_owner, a map
of owner to {backlog_us, decode_count}. These are outstanding prefill work and
active decodes respectively. Exclude this router's owner before summing external
work; local reservations supply its own workload exactly once. Ordinary vLLM
total running/waiting metrics are not interchangeable with this scoped export.

Snapshot timestamps are integer microseconds. Values must be finite and
nonnegative, decode_count and sample_seq are nonnegative integers. Future or
invalid samples are ignored without discarding the previous valid sample.
sample_seq must strictly increase per endpoint: duplicate and older snapshots
do not refresh observation age. An observation is usable exactly when
0 <= now-observed_at_us <= max_age_us. No observation or expired observation
is unavailable, never zero load. A fresh valid sample immediately restores
eligibility. Topology lifecycles and reusing an endpoint identity are out of scope.

## Ownership and generated-token boundary

Accepting a request reserves only its predicted prefill service work (correction
times surface), not its queue wait or transport overhead. Concurrent admission
must observe all previously accepted reservations even if no new backend
snapshot arrived. No prescribed lock, queue, table or internal object layout.

The first nonempty generated `choices[*].text` moves its reservation from
prefill to one local decode. Empty choices, empty text, keepalive comments,
headers and [DONE] do not constitute a token. The supported SSE stream consists
of UTF-8 data events separated by LF/LF or CRLF/CRLF; arbitrary chunk boundaries
may split framing, JSON and UTF-8. All bytes still forward unchanged.

Successful stream completion releases decode ownership. Connection failure,
stream failure, client disconnect or cancellation releases the current stage.
Repeated terminal notifications are harmless. Releasing prefill subtracts the
original reserved amount, even when feedback has since changed correction.
A stream that never produced a token is failed for the task's completion metric.

## Service feedback

The CPU backend diagnostic headers x-service-sample, x-baseline-us and
x-service-us describe one backend prefill service span and its uncorrected
calibration baseline. They exclude queue and transfer time. They become usable
only once this request has produced a generated token. Invalid, missing or
zero-baseline spans do not update calibration. Duplicate (endpoint, sample)
does not update again; sample IDs may be shared across endpoints.

For ratio=service/baseline, update that endpoint only:

    correction = clamp((1-alpha)*correction + alpha*ratio, lower, upper)

Initial correction is 1. Parameters are in the configuration. Also keep the
last window_samples valid ratios. Before the window fills, status is
insufficient_data; mean ratio strictly above drift_upper is slow, strictly
below drift_lower is fast, otherwise normal. A later window can recover.
Explicit delayed feedback via the public gateway API has identical semantics.
No future response observation may influence an earlier placement.

## Embedding interfaces

`DeadlineGateway(configuration, clock, transport, tokenizers=None)` builds the
same main_router completions endpoint used by production-stack. transport is
an aiohttp-compatible request context manager; clock exposes now_us(). Public
adapters: observe(snapshots), cache(claims, available=True),
state(endpoint_id, healthy=True, draining=False), feedback(endpoint, sample_id,
baseline_us, service_us), terminal(request_id, success=False), inspect(), and
summary(start_us, end_us). These support production embedding and CPU exercises.
Internal packages may be reorganized freely while these entry points remain.
